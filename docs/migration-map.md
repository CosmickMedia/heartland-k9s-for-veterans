# Migration map — every live URL and where it goes

Source: https://heartlandk9s.org/ (WordPress 7.1 + Avada/Fusion Builder, 40 published pages, 0 posts, 244 media, 2 FooGalleries). Discovery data: `discovery/live/inventory.json`, `discovery/live/media-manifest.json`, `discovery/live/galleries.json`.

How the migrated pages were produced:

- `tools/fusion-to-blocks.mjs` converts the rendered Fusion markup of each live page into clean core block markup (headings, paragraphs, lists, separators, image/gallery/file/video/buttons blocks) with import tokens (`{{media:live:media:<id>}}`, `{{post_url:live:page:<id>}}` …). Inline styles, Fusion classes, animation attributes, `[ccf_form]`/`[fusion_*]` shortcodes, empty `<h1>` spacers and Figma paste comments are stripped. The original rendered HTML is kept for traceability in `payload-src/source/live__page__<id>.html` (gitignored) next to the full uncurated conversion (`…blocks.html`); the curated content that a page record actually attaches lives in `payload-src/content/live__page__<id>.html`. Per-page curation rules (what moved into template sections, what was removed) are the `PAGE_RULES` table inside the converter and are listed in the Notes column below.
- `tools/extract-registry.mjs` turns the 15 BarKode record pages + the master template into `hk9_barkode` records (`payload-src/records/barkode/`, gitignored because they carry personal contact details).
- Page records: `payload-src/records/pages/live-*.json` (migrated live pages) and `ref-*.json` / `new-*.json` (reference-design pages, authored separately).
- Redirect rules: `payload-src/records/redirects.json` (seeded into the plugin's `hk9_redirects` option; 301 unless stated).

Legend — Disposition: **Migrated** (page kept at the same URL, converted to blocks + template sections), **Decomposed** (page content became CPT records; the page keeps its URL as a listing), **Replaced** (URL kept, content replaced by the reference-design page), **Draft** (imported unpublished for traceability), **Registry** (BarKode record; canonical URL moves under `/barkode/`), **Redirect** (URL only exists as a redirect).

## Cross-cutting decisions recorded here

- **Internal links** inside migrated content are rewritten to tokens by path (`discovery/live/inventory.json`): `/contact/` → `ref:page:contact`, `/` → `ref:page:home`, `/barkode/` → `ref:page:barkode`, `/success/*` → `ref:page:stories`, everything else → `live:page:<id>`. Upload links (`.pdf`, `.docx`) → `{{media_url:live:media:<id>}}`. External links keep their URL; buttons open external links in a new tab with `rel="noopener"`; internal page links never open a new tab. No unknown media or unknown internal link remained after the run (`payload-src/source/fusion-to-blocks-report.json`).
- **Alt text**: file-name-derived alts (e.g. `1000016218`, Facebook `…_n`) are blanked; genuine alts are kept; where the live `<img>` had no alt the media-library alt is used.
- **Headings**: the page title is the only H1 (hero); Fusion "size one" titles become H2; nested `<h1><h2>…` keep the inner level; "headings" longer than 140 characters (Fusion styled paragraphs) become paragraphs.
- **Text left verbatim on purpose** (flag for the client, see `docs/conflict-log.md`): "does not provided funding" (3093); 16-months vs 14-months K9 age (3084); "Retreival" in a registry task line; the 2020 privacy policy wording; "Chris Flemming"/"Chris Fleming" spelling on Meet the Team (person records).
